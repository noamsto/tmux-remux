# tmux 3.8 triggers: rendered tmux.conf, monitor-hook save timer, payload-correct close events

Issue: [#62](https://github.com/noamsto/tmux-remux/issues/62)

## Problem

tmux 3.8 replaced the notification system with events that carry key/value
payloads. A hook now sees `#{hook_<key>}` only for keys its event actually set,
and `pane-exited` sets `pane`, `window` and exit status — **not** session. The
wiring tmux-remux ships today therefore passes `--session=` and
`--session-name=` empty on tmux 3.8, which silently breaks cascade dedup
(`closeevent.Capture`) and the session attribution that `undo --pop` and the
close picker depend on. This is a live regression, not a hypothetical: the
plugin's own development machine runs `next-3.8`.

Two smaller things ride along. 3.8 adds monitor hooks — a server-side periodic
format evaluation — which can replace the external 60s save timer that lazytmux
ships as a systemd unit on Linux and a launchd plist on macOS, along with its
`TMUX_TMPDIR` socket-discovery dance. And the hook fragment itself now has to
differ by tmux version, which the current arrangement cannot express: the same
hooks are hand-maintained in two escaping regimes, bash-constructed
`tmux set-hook` calls in `tmux-remux.tmux` and `'\''`-spliced lines in
`examples/tmux.conf`.

## Verified tmux behavior

Probed on `tmux next-3.8` against throwaway sockets, cross-read against tmux
master sources (`events.c`, `events-payload.c`, `hooks.c`, `monitor.c`,
`server-fn.c`). Measurements, not assumptions.

### Payload keys by event

`event_payload_add_formats` (`events-payload.c`) exposes one `#{hook_<key>}` per
payload key, plus `#{hook_<key>_name}` for session and window items. Anything
the event did not set expands empty.

| Event | `hook_pane` | `hook_window` | `hook_session` | `hook_session_name` | Also |
| --- | --- | --- | --- | --- | --- |
| `pane-exited` | ✓ | ✓ | **empty** | **empty** | `hook_window_name`, `hook_exit_status`, `hook_exit_signal`, `hook_exit_success` |
| `window-unlinked` | — | ✓ | ✓ | ✓ | `hook_window_index` |
| `session-closed` | — | — | ✓ | ✓ | — |
| `window-closed` (new in 3.8) | — | ✓ | empty | empty | — |
| `after-kill-pane` | **empty** | **empty** | **empty** | **empty** | `hook_arguments`, `hook_argument_N`, `hook_flag_t` |

Inside `pane-exited` the *target* is correct even though the payload has no
session: `#{session_id}` expanded to `$1` and `#{session_name}` to `target` for
a pane in session `target` while another session was current. `server_fire_pane_exit`
sets the target from `cmd_find_from_pane(wp)`, so this is by construction, not
luck.

The same is **not** true of `after-kill-pane`: `#{pane_id}` there expanded to a
pane in an unrelated session. That matches the existing finding in the
session-aware undo spec and is why the survivor-diff stays (below).

### `after-kill-pane` still cannot name its victim

`server_kill_pane()` — the `prefix+x` path — fires no pane event at all. It
calls `server_unzoom_window` / `server_client_remove_pane` /
`layout_close_pane` / `window_remove_pane` directly; only `server_destroy_pane`
(a program exiting) reaches `server_fire_pane_exit`. `after-kill-pane` carries
`hook_flag_t` only when `-t` was passed explicitly, and the default binding
(`confirm-before … kill-pane`) passes nothing. Probe: `kill-pane -t %1` gave
`hook_pane=` empty, `hook_flag_t=%1`, `hook_arguments=-t "%1"`.

**Consequence: the survivor-diff in `closeevent.resolveKilledPane` is not
removable.** Issue #62's proposal 2 does not pan out.

### Monitor hooks

`#{t:%M}` — the snippet in the issue — expands to **empty**. `t:` formats a time
*variable* (`#{t:start_time}` → `Mon Aug 10 08:20:51 2026`); it is not
strftime-of-now. `T:` re-expands a variable's *value* through strftime
(`FORMAT_EXPANDTIME`, `format.c`), so the format string must live in an option:

| Expression | Result |
| --- | --- |
| `#{t:%M}` | empty |
| `#{T:%M}` | empty |
| `set -g @x '%M'` then `#{T:@x}` | `21` — the current minute |

A **global** monitor hook survives session churn. `hooks_monitor_add` is passed
`s = NULL` when the option is global (`cmd-set-option.c` only sets `s` for
non-global option scopes), and `monitor_get_session` falls back to
`RB_MIN(sessions)` when `ms->session` is NULL. Probed: created the monitor,
killed the lowest-id session, ticks continued and reported the surviving
session. With zero sessions `monitor_get_session` returns NULL and the timer
re-arms without firing — which is exactly when a timer save is a no-op anyway.

Firing is once per observed value change, checked on a 1s timer. Over 4s with
`%S` the log showed values `07, 08, 10, 11, 12` — one fire per change, values
may skip, fires are not lost. At `%M` granularity that is one fire per minute.

### Mechanism availability

| Feature | Since |
| --- | --- |
| `source-file -` (read config from stdin) | tmux 3.1 |
| `set-hook -B` monitor hooks | tmux 3.8 |

`source-file -` predates everything tmux-remux already requires
(`display-popup` alone needs 3.2), so piping a rendered fragment into tmux needs
no version gate.

## Decisions

**One renderer owns every hook string.** A new `internal/triggers` package
renders the tmux.conf fragment; `tmux-remux.tmux`, `examples/tmux.conf` and
(later) lazytmux all consume that one output. Today's arrangement keeps the same
hooks in two hand-maintained escaping regimes, and a version-dependent fragment
would make that three.

**The version gate lives in Go, and the pre-3.8 branch is frozen verbatim.**
`triggers` detects tmux via `tmux -V` and renders one of two fragments. The
`< 3.8` fragment reproduces today's known-good hook strings unchanged, modulo a
generated-file header — freezing it is the point of gating, so no pre-3.8 user
is exposed to this change.

**`pane-exited` reads its session from the target on 3.8.** `#{session_id}` /
`#{session_name}` in place of `#{hook_session}` / `#{hook_session_name}`.
`window-unlinked` and `session-closed` keep `hook_*` — their payloads carry it.

**The survivor-diff stays.** See the verified behavior above.

**`examples/tmux.conf` becomes generated** — a golden test asserts it equals the
3.8 render. It is still a file people read, but it can no longer drift from the
code that ships.

**`triggers` emits the whole fragment**, hooks and auto-restore and
keybindings. Splitting them would add a flag whose only consumer is a
hypothetical user who wants tmux-remux's hooks but not its keys; `tmux-remux.tmux`
and `examples/tmux.conf` both want all three today.

## Component 1: `internal/triggers`

Pure rendering, no I/O, so the whole quoting surface is testable without a tmux:

```go
type Params struct {
    Bin         string       // path the hooks invoke
    Version     tmux.Version
    AutoRestore bool
}

func Render(p Params) string
```

Because the output is sourced by tmux rather than built in bash, only one
escaping regime survives — the `examples/tmux.conf` one. The bash-side quoting
rules documented in `tmux-remux.tmux:123-140` (tmux stripping outer quotes when
a hook fires, `sh -c` re-parsing `$38` as a positional parameter) stop applying
to the plugin script entirely; the equivalent tmux.conf rules move into this
package as comments on the template.

### 3.8 fragment (differences from today)

```tmux
# #{t:%M} does not work: t: formats a time *variable*, not strftime-of-now.
# T: re-expands a variable's value through strftime, so the format string has
# to live in an option.
set -g @remux_save_tick '%M'
set-hook -g -B '@remux-save:session:#{T:@remux_save_tick}' 'run-shell -b "<bin> save --reason=timer"'

# 3.8 payloads carry no session for pane events; the event target does.
set-hook -g pane-exited 'run-shell -b "<bin> capture-event pane-died --pane=#{hook_pane} --window=#{hook_window} --session='\''#{session_id}'\'' --session-name='\''#{session_name}'\''"'
```

Everything else — `session-created`, `window-linked`, `after-split-window`,
`client-detached`, `after-kill-pane`, `window-unlinked`, `session-closed`, the
binds, `restore --auto` — is unchanged from the pre-3.8 fragment. The
event-driven save hooks stay: the monitor is a floor, not a replacement for
responding to structural change.

`@remux_save_tick` is deliberately a real option rather than an inlined
constant — it is the only way to reach strftime, and exposing it lets tests
drive the monitor at `%S`.

## Component 2: `tmux.Version`

`internal/tmux` gains a version type and parser. `tmux -V` prints `tmux 3.5a`,
`tmux next-3.8`, `tmux 3.4`; the parser yields a comparable major/minor,
treating `next-N.M` as `N.M` (a `next-3.8` build has the 3.8 features — the
probes above ran on exactly such a build).

Detection runs once per `triggers` invocation. `--tmux-version` overrides it so
Nix can render at build time against its pinned tmux and so golden tests can
pin both branches without needing two tmux binaries installed.

## Component 3: `tmux-remux triggers`

```
tmux-remux triggers [--bin=PATH] [--tmux-version=X.Y] [--auto-restore=on|off]
```

`--bin` defaults to `os.Executable()`, which is already the right answer for
the TPM path (the resolved or downloaded binary is the one running). It exists
for the generated-docs case, where `examples/tmux.conf` wants the literal
string `tmux-remux`.

`--auto-restore` replaces the `@tmux_remux_auto_restore` shell conditional; the
`run-shell -b '<bin> restore --auto'` line moves into the fragment.

## Component 4: `tmux-remux.tmux`

`wire_plugin` collapses to one pipe:

```bash
if ! "$bin" triggers --auto-restore="$auto_restore" | tmux source-file -; then
  tmux display-message "tmux-remux: binary too old for this plugin version — update or unpin @tmux_remux_version"
fi
```

The failure branch is the one thing the script must still gate, and it is about
the **binary** version, not tmux's. TPM ships this script from git while the
binary can be pinned by `@tmux_remux_version` or served stale from the plugin's
`bin/` cache, so a script that hard-depends on `triggers` can meet a binary
without it.

The fallback is a message, deliberately **not** an inline copy of the legacy
hooks. Re-embedding them in bash would recreate the second maintained copy this
design exists to delete.

`resolve_binary`, `detect_os`, `detect_arch`, `download_release_binary` and the
checksum verification are untouched.

## Error handling

A `triggers` run that cannot determine the tmux version (no `tmux` on PATH,
unparsable `-V`) is a hard error on stderr with a non-zero exit, which the TPM
script surfaces via the `display-message` branch above. Rendering a guessed
fragment would be worse than rendering none: a 3.8 fragment sourced by a 3.7
tmux fails on `set-hook -B` with a parse error mid-file, leaving the hooks
half-wired.

Inside tmux, a monitor hook whose command fails is already `run-shell -b`, so
failures land in tmux-remux's own log exactly as the timer's did.

## Testing

**Golden renders** (`internal/triggers`) — one file per version branch, with a
`-update` flag. The pre-3.8 golden is seeded from `examples/tmux.conf` as it
stands *before* this change, so any drift from the frozen fragment fails the
build. (After this change `examples/tmux.conf` is the 3.8 render.)

**Generated-docs check** — a test asserting `examples/tmux.conf` equals
`Render(Params{Bin: "tmux-remux", Version: 3.8, AutoRestore: true})`.

**Version parsing** — table test over `tmux 3.4`, `tmux 3.5a`, `tmux next-3.8`,
and a malformed line.

**Integration, real tmux** (extends the existing `testutil` socket harness):

1. Source the rendered fragment into a live server, then close a pane (program
   exit), unlink a window, and close a session; assert each stored event carries
   the correct session id **and** name. This is the test that would have caught
   the current regression — it exercises the quoting through all three levels of
   re-parsing, which a golden file cannot.
2. Kill a pane with `prefix+x` semantics (`kill-pane` with no `-t`) and assert
   the survivor-diff still resolves it — guarding the path issue #62 proposed to
   delete.
3. Override `@remux_save_tick` to `%S`, wait, and assert a `reason=timer`
   snapshot lands. Skipped when the detected tmux is below 3.8.

## Out of scope

**Dropping lazytmux's save timer.** The systemd unit, its macOS launchd
equivalent, and the `TMUX_TMPDIR` dance are removable once this ships, but they
live in another repo and cannot merge before `triggers` exists. Follow-up PR
there; the weekly GC timer stays either way, since GC's whole point is running
when no server is live.

**New payload data.** `hook_exit_status` / `hook_exit_signal` /
`hook_exit_success` on `pane-exited` and the new `window-closed` event are real
3.8 capabilities — an exit code could label a close row in the picker — but
nothing in #62 needs them. Separate issue.

**The snapshot engine.** Unchanged: `state.db`, scrollback capture, the undo
stack, pickers, restore modes. This is trigger plumbing only.
